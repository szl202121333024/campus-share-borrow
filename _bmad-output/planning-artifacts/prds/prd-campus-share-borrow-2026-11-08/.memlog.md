- (decision) 账号来源：预置种子账号（学生+管理员），学号+密码登录，不做注册流程 —— 演示可复现，PRD 少一条 FR
- (decision) 班级可见性：物品属某班级，用户只可见/可借本班物品 —— 让「不做跨班共享」可验收
- (decision) 物品模型：图书与器材统一建模，用 category 区分 —— 借阅/归还/限额逻辑只写一份（NFR-2）
- (decision) 物品粒度：一条物品记录=一个可借单位，同款多件录多条 —— 使「在借」判定落在单条记录，配合唯一索引
- (override) 人类保留一物一行模型，但强制要求：PRD 写明「管理员录入成本变高」的代价，并用并发 409 测试验证；记 ADR-006
- (override) 人类否决 class_id 预留：YAGNI + NFR-2，砍掉 class 概念，多班级写入后续扩展（多租户/多实例），不留死字段
- (override) 人类修改：新增「停用/下架」状态（unavailable），在借物品可停用、仍可归还、归还后不展示；不提供强制删除以保护审计链
- (override) 人类否决「未登录不可浏览」：允许访客匿名 GET /items 与搜索，仅 POST /borrow 要求登录，写入 FR-1 验收
- (event) PRD 第 2 节落稿：FR-1（登录/会话/访问控制，含访客匿名只读与 403 越权）与 FR-2（列表与关键字搜索，访客不显示借阅人姓名）
- (override) 人类裁决：保留「恢复上架」；停用物品归还照常写 returned_at，状态保持 unavailable 直到管理员手动恢复 —— 写入 FR-6/FR-4 验收
- (event) PRD 第 3 节落稿：FR-3 借阅（含并发保证、错误判定顺序、原子性、物品名称快照）
- (decision) D-006 人类确认限额优先于冲突：事务内先 COUNT 再 INSERT，反序需物品级锁
- (override) D-007 人类否决借阅历史视图与 item_name_snapshot 字段（YAGNI，省 1-2 个故事）
- (override) D-008 人类补验收：存在性与停用状态必须同一次查询判定；双击重复提交两条拦截路径统一 409 + 统一文案
- (override) D-009 人类加严：借阅写操作必须在 BEGIN IMMEDIATE 事务内校验额度后 INSERT，禁 DEFERRED，写入阶段 3 project-context.md；与 ADR-002 措辞需对齐
- (override) D-009 分工确认：BEGIN IMMEDIATE 管额度原子性，唯一索引管唯一性裁决；ADR-002 否决项改为「仅靠应用层 SELECT 或单纯加写锁防超卖」，playbook 已同步
- (override) D-010 裁决：删除物品时级联删除已归还记录；有未归还记录则 409 拦截。写入 FR-6 验收
- (event) PRD 第 4 节落稿：FR-4 归还（停用归还走完流程但状态不变、重复归还 409、越权归还 404）与 FR-5 限额（含逾期占额度、并发越限不成立）
- (decision) D-011 否决 403 语义纯度，统一 404 RESOURCE_NOT_FOUND，防借阅记录越权枚举
- (decision) D-012 管理员不豁免限额（YAGNI），project-context 加「所有角色统一业务规则，无权限豁免」
- (decision) D-013 额度计算复用单一服务层函数 get_remaining_quota，单条 SQL 聚合，禁 N+1 与第二份计数 SQL
- (override) D-014 归还只写 loans 表，禁改 items.status；物品状态改为派生展示态（available/unavailable 存储，borrowed 由查询派生），配两条独立测试
- (decision) D-015 人类通过并升格为 ADR-007：物品状态机采用「存储态+派生态」混合模型，items 只存 available/unavailable，borrowed 由 loans 派生
- (override) D-013 理由重写：不存在的 N+1 风险被移除，规则真实目的是防止两处计数逻辑漂移（NFR-2）
- (override) D-011 理由重写：放弃站不住的「防越权枚举」，改为「分支简单 + 掩盖资源存在性」，合 RESTful 惯例
- (decision) 错误约定放宽：404 一律表示目标资源不可见或不存在，RESOURCE_NOT_FOUND 为唯一例外，不拆分
- (event) PRD 第 5 节落稿：FR-6 管理员（新增/删除含级联/停用/恢复上架/不得代还/受限额）、NFR-1 并发一致性 5 条可测验收、NFR-2 一条命令启动、§6 明确不做 9 条 + 后续扩展
- (event) Reviewer Gate：adversarial 评审判 FAIL，修复 17 项（判定顺序冲突、ADR 计数 5→7、NFR-2 命令与技术栈无关、§5/§6 引用、UJ/FR/D 交叉引用、文案统一等）
- (decision) D-016 提出：D-006 与 D-008 在「满额双击」场景互斥，提议插入「本人已持有」前置校验（④）以同时满足两者，待人类确认
