# ADR-006 · 物品模型：一物一行的单件实体

**决定：`items` 表一行 = 一个可借实物，数量恒为 1，不设 `quantity` / `stock` / `remaining` 任何计数列。同款多件由管理员录入多条独立记录（「胶枪 #1」「胶枪 #2」），各自独立借还。**

**否决的备选：库存数量字段（`quantity`）；书目 + 副本双表；同款合并 + 剩余数；无外键 + 名称快照的软引用；物品组自动编号。**

## 1. 背景

PRD 把「物品」定义为「一条物品记录 = 一个可借单位（数量恒为 1）」，并要求「同一物品同一时刻最多存在 1 条在借记录」（§3 在借、NFR-1.1）。这两句话决定了建模粒度：**一张表的一行到底是「一种东西」还是「一件东西」**。

选错粒度的后果不是抽象的：如果一行代表「一种东西」（例如「胶枪，库存 3」），那么「同一时刻最多一条在借」这条不变量就必须表达成「在借数 ≤ 库存数」——这是一个**计数约束**，而计数约束无法落成数据库唯一索引，只能回到应用层先查后写（即 ADR-002 已否决的 TOCTOU 写法）。

物品规模被锁定在单班 ≤ 50 条（PRD A-1、Q-3），且不做分页、不做详情页。这个规模足够小，允许用「多录几行」换取「不变量可被物理表达」。

## 2. 决定

- **`items` 一行 = 一件实物**，字段只有 `id, name, category, status, created_at`——**没有数量列，任何形式的数量列都没有**。
- 同款多件 → **多条记录**，靠名称区分（「胶枪 #1」「胶枪 #2」）。名称允许重复，**不做唯一性校验**（FR-6 明确规定）。
- **「剩余可借数」不是存储字段**：需要时由 `COUNT` 派生（该物品是否存在未归还记录），与 ADR-007 的派生态一致。
- **停用与删除作用于单件**：一台投影仪坏了，就停用「投影仪 #1」，其余同款照常可借（直接支撑 UJ-3、FR-6）。
- 该粒度使 ADR-002 的部分唯一索引 `ON loans(item_id) WHERE returned_at IS NULL` **可以直接表达「一件实物同时只能被一个人持有」**——索引是声明式的，不需要任何写入方记得做检查。

## 3. 否决的备选方案

### 3.1 备选一：库存数量字段（`items.quantity` / `remaining`，初始的"更自然"选择）

**方案**：`items(name, quantity)`，借阅时 `UPDATE items SET quantity = quantity - 1 WHERE id = ? AND quantity > 0`，归还时 `+1`。

**否决理由（诚实版：它不是绝对写错，而是更弱、更易错、且损失业务表达力）**：

1. **不变量无法声明式表达** —— 「同一时刻最多 1 条在借记录」在计数模型里变成「在借数 ≤ 库存数」，唯一索引无法约束计数，正确性只能靠每次写入都记得做 `rowcount` 检查 + 与 `INSERT` 同事务。**这恰好把系统逼回 ADR-002 已否决的「靠应用层判断」路线**。
2. **两处写必须永远同步** —— 扣数量与写借阅记录是两条语句，任意一侧失败/漏写就产生「数量与记录不一致」的静默脏数据；而单件模型下「在借」是派生的，压根不存在第二份数据（ADR-007）。
3. **停用/删除粒度变粗，直接与 FR-6 冲突** —— 库存模型里「3 支胶枪坏了 1 支」只能把数量改成 2，**无法表达「坏的是哪一支、正在被谁借」**；UJ-3「下架一台坏掉的投影仪」要求的是按件操作，库存模型做不到。
4. **归语义模糊化** —— 计数模型天然诱导「归还任意一件同款、系统自动换号」，而 PRD 明确 v1 不做这类宽松体验。

### 3.2 备选二：书目 + 副本双表（`items` + `item_copies`，图书馆标准模型）

**方案**：`items` 存书名/类别等共享属性，`item_copies` 存每一册，`loans` 外键指向 `item_copies.id`。

**否决理由**：这是**业界更规范**的模型，原则上更不容易错，但在本项目的规模与工期下不划算：① 多一层 JOIN 与多一套录入流程（先建书目、再建 N 个副本），管理员操作步骤翻倍；② 多 1–2 个用户故事的实现量；③ 50 条规模下「同款书名重复存储」的成本可忽略，规范化收益接近零。**若物品规模上千或要做馆藏管理，这是应该换回的模型**——记录为升级路径，v1 不用。

### 3.3 备选三：同款合并 + 剩余计数（备选一的变体）

**方案**：`items(name, total, available)`，一条记录代表「胶枪 ×5」。

**否决理由**：同 3.1，且更糟——多了一个需要维护的冗余字段（`available` 与 `total` 必须同步），是「双份真相」的教科书案例，与 ADR-007 的核心原则直接矛盾。

### 3.4 备选四：无外键 + 在借阅记录里存物品名称快照（软引用）

**方案**：`loans` 存 `item_name` 文本而非 `item_id` 外键，物品删除后历史记录仍可读。

**否决理由**：① D-007 已砍掉借阅历史视图与快照字段，快照的收益（历史可读）在本期不存在；② 快照会让同一物品在不同记录里出现不同名字（改名漂移），破坏 ADR-007 依赖的「物品名称单一真相」——这也是 FR-6 拒绝「物品编辑」功能的同一个理由；③ 失去外键后，删除物品会留下孤儿记录，与 D-010「级联清理」的设计冲突。

### 3.5 备选五：录入「胶枪 ×5」由系统自动展开为 5 行（物品组 + 自动编号）

**方案**：管理员填一次「胶枪」+ 数量 5，系统自动生成 `胶枪 #1..5`。

**否决理由**：方向正确（保留单件实体，只优化录入），但引入了「组」这一额外概念——组的改名、删除、停用语义都要单独定义，还要处理同名冲突与部分删除；而 v1 的物品总数 ≤ 50 条、且是一次性录入（种子数据 + 偶尔增补）。**用一次性的人工重复提交换掉一个长久的抽象，是划算的**。若日后录入频繁，可作为管理员页面的纯前端便利功能加回，不改变数据模型。

## 4. 后果

**正面**

- **不变量可物理表达**：ADR-002 的部分唯一索引直接落地，超卖在数据库层面不可能发生。
- **状态单一真相**：无计数缓存 → 无漂移（ADR-007）。
- **按件粒度吻合业务**：停用某一件坏的、删除某一件不再提供的，互不影响（FR-6、UJ-3）。
- 借阅记录天然指向具体实物，「哪一件」不需要二次分配。
- 表结构与查询都更简单：`items` 只有 5 列，列表页一次查询搞定。

**负面 / 明确接受的代价（D-001 要求在 PRD 中写明，已写入 §3 物品）**

- **录入成本变高**：同款 5 件要录 5 次。缓解：种子脚本预置演示数据；管理员一次性录入；备选五的"自动展开"可在不改变模型的前提下后补。
- **不支持「归还任意一件同款、系统自动换号」**：借阅与归还严格绑定到具体记录（PRD 明确不做）。
- **规模上限 ≤ 50 条**（PRD A-1）：超过需重新评估分页与索引（Q-3）。这不是模型硬限制，而是"不做分页"这个产品取舍的依据。
- **名称重复无约束**：列表里可能出现两个都叫「胶枪」的记录，靠管理员命名习惯区分，不做校验（FR-6 明确允许重复）。

## 5. 下游含义（供阶段 3/4 引用）

- `items` 表**禁止**出现 `quantity` / `stock` / `available_count` / `borrowed_count` 任何计数列——出现即为违反本 ADR。
- 任何「还剩几件可借」的展示，必须由借阅记录 `COUNT` 派生，不得读缓存列。
- 管理员新增物品的接口一次只接受**一条**记录（名称 + 类别）；批量录入属超范围（PRD §6 明确不做批量导入）。
- 种子数据必须包含同款多件的示例（如「胶枪 #1」「胶枪 #2」），用于演示「同款独立借还」。
- 与 ADR-002 的接口：唯一索引建在 `loans(item_id)` 上，正因本 ADR 保证「一行 = 一件」，该索引才等价于「一件实物只能被一个人持有」。
